# Benchmark、Baseline 与完整实验验证计划

## 1. 总体目标与执行原则

实验体系围绕四个问题组织：算法是否优于合理对照、优势是否随规模保持、优势来自哪些模块、结论是否在实例与随机重复上稳定。所有算法必须调用同一个 `evaluate_capacity_solution`，使用相同三目标、实例、资源参数和评价预算；实例随机性与求解器随机性分开管理。

正式目标统一为：最小化累计未满足率 `unmet_area`、最小化配送—修复加权时间 `time_cost`、最小化最低满足率的相反数 `neg_min_satisfaction`。核心质量指标为归一化 Hypervolume（越大越好）、IGD（越小越好）和非支配解数；辅助指标为最终总/最低满足率、平均可达率、修复率、运行时间和目标函数评价次数。

## 3. Benchmark 设计（已实现）

### 3.1 数据集矩阵

正式套件不是笛卡尔积爆炸，而是显式登记的七类实例。真实案例用于内部有效性；合成案例用于规模扩展和外部有效性。

| case | 类型 | 规模层 | 节点 | 目标边密度 `gamma` | 损坏率 | 默认实例种子 |
|---|---|---|---:|---:|---:|---:|
| WEN38 | 汶川案例 | case study | 38 | 原始 51 边 | 16/51 | 1–30 |
| S025 | 脆弱走廊合成 | small | 25 | 3 | 0.15 | 1–30 |
| S050 | 脆弱走廊合成 | small | 50 | 4 | 0.30 | 1–30 |
| M100 | 脆弱走廊合成 | medium | 100 | 3 | 0.15 | 1–30 |
| M200 | 脆弱走廊合成 | medium | 200 | 4 | 0.30 | 1–30 |
| L400 | 脆弱走廊合成 | large | 400 | 3 | 0.15 | 1–30 |
| L800 | 脆弱走廊合成 | large | 800 | 4 | 0.30 | 1–30 |

合成网络采用无向、简单、连通随机图，不预设区域、社区或关键走廊；供给点、需求点和受损道路均随机抽取。每类车辆数量按需求规模校准，使每个决策期的名义车队运力约为总需求的 14%，避免第一期耗尽全部物资，并使累计未满足程度和期末最低满足率均保留方案区分度。`capacity_scale=0.05` 和 `fleet_capacity_ratio=0.14` 均为受控实验参数，不得写成现场标定值。

三套执行配置：

- `smoke`：20/60/120 节点，各 1 个实例种子、1 次求解重复、12 次目标评价，只用于持续集成和机制检查。
- `benchmark`：WEN38 + 25/50/100/200/400/800 节点，5 个实例种子、10 次随机算法重复、500 次目标评价，用于开发期比较。
- `publication`：相同七类案例，30 个实例种子、30 次随机算法重复、10,000 次目标评价，用于论文正式结果。正式运行前应依据 pilot 的耗时结果决定是否按规模设置等时预算；任何调整必须预先登记。

### 3.2 评价维度

算法性能同时从四方面报告：

1. 求解质量：HV、IGD、Pareto 解数、三个代表解目标值。
2. 运行效率：墙钟时间、目标评价次数、单位评价时间。
3. 扩展能力：对 `log(N)` 回归 `log(runtime)`，报告经验复杂度斜率；绘制 HV/IGD 随规模变化。
4. 可行与服务表现：最终总满足率、最低满足率、可达率、修复率、容量阻塞量。

不能把 smoke 数值作为论文结论；它只验证数据区分度和流水线完整性。

## 4. Baseline 体系（已实现）

| 标识 | 方法 | 类型 | 公平比较方式 | 作用 |
|---|---|---|---|---|
| `spt` | 最短修复工时优先 + 最早空闲维修队 + 最近供需配送优先 | 经典构造启发式 | 确定性运行一次；同一评价函数 | 给出低成本、可解释下界式对照 |
| `vnd` | swap / insert / 队伍重分配 / 配送顺序调整的变邻域下降 | 局部搜索 | 与进化算法相同目标评价预算 | 判断单纯邻域改进是否已足够 |
| `nsga2` | 非支配排序、拥挤距离、交叉与变异 | 经典多目标进化算法 | 相同种群参数和评价预算 | 隔离多目标进化框架本身的贡献 |
| `nsga2_alns` | NSGA-II + 自适应算子权重 + 退火接受的多邻域搜索 | 拟议先进混合方法 | 与 NSGA-II 完全相同总评价预算 | 检验自适应邻域混合是否改善前沿质量 |

NSGA-II 的标准来源为 [Deb et al. (2002)](https://doi.org/10.1109/4235.996017)。ALNS 源自 [Ropke and Pisinger (2006)](https://doi.org/10.1287/trsc.1050.0135)，且 2025 年的系统综述汇总了 211 篇 VRP-ALNS 研究及算子实践 [Voigt (2025)](https://doi.org/10.1016/j.ejor.2024.05.033)。2024 年动态多仓车辆路径研究仍使用 ALNS 重优化框架，说明它是当前动态 VRP 的活跃代表方法 [Computers & Industrial Engineering 191 (2024) 110122](https://doi.org/10.1016/j.cie.2024.110122)。

统一设置包括：相同实例对象、相同三个最小化目标、相同 `instance_seed`；随机算法在同一 `solver_seed` 下配对，并严格共享 `max_evaluations`。输出显式区分 `instance_seed` 与 `solver_seed`。确定性 SPT 不复制 30 次，避免把重复的相同值当作独立样本。

## 5. 深入实验分析计划（待执行）

### 5.1 消融与模块组合

单模块消融至少包括：

- `NSGA-II+ALNS -> NSGA-II`：删除局部搜索。
- 自适应权重 -> 均匀随机算子：识别自适应选择贡献。
- 退火接受 -> 仅改进接受：识别跳出局部最优的贡献。
- 渐进容量 -> 二元开放：识别容量渐进恢复贡献。
- 多车型阈值 -> 统一车型：识别异质通行贡献。
- 边—周期吞吐 -> 不限容量：识别容量约束贡献。
- rolling -> expected-state open-loop：在共同维修效率随机实现下识别信息价值。

模块组合采用 `2^3`：自适应权重、退火接受、滚动反馈三个开关全组合；容量恢复、车型阈值和吞吐约束作为模型机制单独做 `2^3` 组合。主效应和二阶交互效应均在同实例同种子上配对估计。

### 5.2 参数敏感性

算法参数：`pop_size={50,100,200}`、`pc={0.7,0.8,0.9,1.0}`、`pm={0.05,0.1,0.2,0.3}`、`alns_probability={0,0.2,0.35,0.5,0.8}`、`alns_iterations={2,4,8,16}`。模型参数：`capacity_scale={0.02,0.05,0.10,1.0}`、`repair_time_weight={0,0.01,0.05,0.10,0.20}`、维修效率偏差 `delta={0,0.15,0.30}`。先用 Morris/筛选实验定位敏感参数，再对前 3–5 个参数做精细网格，避免完整笛卡尔积。

### 5.3 收敛与搜索特征

所有收敛图以目标评价次数为横轴，不能只用“代数”。报告 anytime HV、IGD、archive 大小、算子选择概率、接受率、支配改进率和解的决策距离。对每种规模绘制中位数曲线与 95% bootstrap 带，并记录达到最终 HV 90%/95% 所需评价次数。

## 6. 统计评价计划（待执行）

实验单位分两层：实例种子描述网络与需求差异，求解种子描述算法内部随机性。算法比较在同一实例种子与同一求解种子上配对；滚动/open-loop 还必须共享逐道路逐周期维修效率实现。

每组报告均值、标准差、中位数、IQR、95% BCa bootstrap 置信区间。两个算法使用配对置换检验或 Wilcoxon signed-rank；三个及以上算法先用 Friedman 检验，再做 Holm 校正的成对事后比较。除 `p` 值外报告配对差的 Hodges–Lehmann 估计和 Vargha–Delaney `A12`（或 Cliff's delta）。跨 7 类案例的检验不得把同一实例上的多个 Pareto 点当作独立样本。

随机种子表、失败/超时记录、原始逐运行结果、环境版本和 Git SHA 全部随复现包保存。若模型、参数或代码改变，旧数值统一标记为 `STALE` 并重跑，不能拼接新旧结果。

## 7. 当前实现与运行方式

新增实现：

- `scripts/reproduce/benchmark_suite.py`：显式规模套件、真实案例和脆弱走廊实例构建。
- `scripts/reproduce/benchmark_algorithms.py`：四种统一预算算法及目标评价计数。
- `scripts/reproduce/run_benchmark.py`：运行、合并参考前沿、HV/IGD、分规模聚合和 manifest。
- `tests/test_benchmark.py`：规模覆盖、可复现、预算一致和指标正确性测试。

快速验证：

```bash
uv run python scripts/reproduce/run_benchmark.py \
  --suite smoke \
  --output-dir outputs/benchmark_smoke
```

开发期 benchmark：

```bash
uv run python scripts/reproduce/run_benchmark.py \
  --suite benchmark \
  --output-dir outputs/benchmark
```

正式运行建议先按单个案例分批提交并保留相同参数，例如：

```bash
uv run python scripts/reproduce/run_benchmark.py \
  --suite publication \
  --cases L400 \
  --output-dir outputs/publication_L400
```

每次运行输出 `instances.csv`、`runs.csv`、`pareto_points.csv`、`convergence.csv`、`aggregate_by_size.csv` 和 `experiment_manifest.json`。其中 `runs.csv` 是统计检验的基本输入，`pareto_points.csv` 用于复核参考前沿，不能互相替代。

## 8. 当前开发级验证结果

已执行 `20/60/120` 节点、随机算法各 3 次、每次 100 个目标评价的开发级试验。下表为各重复均值；SPT 是确定性算法，因此只运行一次。该表只验证基线区分能力，不能替代 30 个实例种子 × 30 次求解重复的论文统计。

| 规模 | 算法 | HV | IGD | 累计未满足率 | 最低满足率 | 时间/秒 |
|---|---|---:|---:|---:|---:|---:|
| small | SPT | 0.975 | 0.506 | 0.900 | 0.900 | 0.01 |
| small | VND | 1.065 | 0.139 | 0.900 | 0.900 | 0.47 |
| small | NSGA-II | 1.036 | 0.082 | 0.900 | 0.900 | 0.47 |
| small | NSGA-II+ALNS | 0.856 | 0.159 | 0.900 | 0.900 | 0.45 |
| medium | SPT | 0.011 | 0.926 | 4.057 | 0.000 | 0.02 |
| medium | VND | 0.051 | 0.612 | 3.333 | 0.217 | 1.77 |
| medium | NSGA-II | 0.312 | 0.167 | 1.397 | 0.759 | 1.97 |
| medium | NSGA-II+ALNS | 0.122 | 0.356 | 2.660 | 0.548 | 1.83 |
| large | SPT | 0.011 | 0.606 | 2.812 | 0.000 | 0.08 |
| large | VND | 0.011 | 0.602 | 2.810 | 0.000 | 7.94 |
| large | NSGA-II | 0.217 | 0.231 | 1.913 | 0.269 | 8.22 |
| large | NSGA-II+ALNS | 0.079 | 0.382 | 2.154 | 0.269 | 7.93 |

在当前极小预算下，NSGA-II 在中、大规模上的平均 HV 和 IGD 优于混合算法，不能预设拟议方法必胜。这个结果把第 3 点中的 ALNS 概率、局部搜索深度、接受准则消融和 anytime 收敛分析变成了必要验证，而不是可选美化。另已完成 800 节点、3200 边、960 条受损边的 SPT 单点评价，端到端耗时约 4.18 秒，证明正式大规模实例能够被当前解码器处理；这同样不是算法性能结论。
