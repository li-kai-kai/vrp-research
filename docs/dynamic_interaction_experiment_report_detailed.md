## 摘要

本实验围绕两个问题展开：渐进道路恢复能否比二元状态更早释放服务能力，以及当实际维修效率导致道路状态偏离期望计划时，观测实际修复进度后滚动重规划是否具有价值。实验构造二元固定、渐进固定、期望状态 open-loop 和状态观测 rolling 四组机制；4 个修复时间倍率与 3 种维修队规模形成 12 个资源设置，并在多个共同维修效率随机实现上成对比较。

旧版实验曾在 12 个资源设置上得到正向机制信号，但旧 open-loop 只固定使用初始状态，并未按期望状态规划完整周期，因此旧百分比不能识别道路状态信息的价值。本报告将其保留在第 5 节作为审计记录，不作为当前摘要结论。

当前实验属于机制验证而非最终算法性能基准。新设计以维修效率随机种子作为模拟重复单位，在同一随机实现内成对比较 open-loop 与 rolling；资源设置不是独立灾害样本。当前数值结论须在正式多种子网格完成后填写。

## 1. 实验目标与研究假设

### 1.1 实验目标

1. 检验多阶段容量恢复能否比“完全修好后开放”的二元状态更早提高需求点可达性。
2. 检验实际修复进度偏离期望计划时，依据已观测道路状态重规划能否降低救援等待。
3. 检验信息价值是否随维修效率偏差、修复难度和维修队规模变化。

### 1.2 可检验假设

| 假设 | 内容 | 主要指标 |
|---|---|---|
| H1 | 渐进恢复相对二元恢复降低累计未满足率和 | 累计未满足率和 |
| H2 | 渐进恢复相对二元恢复提高平均可达率 | 平均可达率 |
| H3 | 当维修效率存在偏差时，状态观测 rolling 相对期望状态 open-loop 降低累计未满足率和 | 配对累计未满足率差 |
| H4 | 维修效率偏差越大或资源越紧张，道路状态信息越可能改变最终可服务范围 | 配对最终满足率、regret |

## 3. 实验设计与方法

### 3.1 四组对照机制

| 机制 | 道路状态 | 修复决策 | 作用 |
|---|---|---|---|
| binary_static | 二元状态 | 按修复时间从短到长排序，轮流分配维修队 | 基准组 |
| progressive_static | 五阶段恢复 + 车型阈值 | 与二元组完全相同的固定修复序列 | 识别渐进恢复效应 |
| progressive_openloop | 五阶段恢复 + 车型阈值 | 按 `E[xi]=1` 和预测供需状态在期初生成全期计划，执行中不改变维修安排 | 无道路状态反馈基准 |
| progressive_rolling | 五阶段恢复 + 车型阈值 | 每周期依据已观测修复进度、实际剩余供给和累计配送量重新选择道路 | 识别道路状态信息价值 |

二元静态与渐进静态使用相同修复计划和同一维修效率实现，差异只来自道路状态与车型通行机制。open-loop 与 rolling 使用相同的候选道路评价规则和共同随机数；前者只在期初基于期望状态生成计划，后者在每期读取实际道路状态后重规划。`delta=0` 是安慰剂检查：没有新信息时二者不应出现系统差异。

### 3.2 资源情景矩阵

| 维修队 \ 修复倍率 | ×1.0 | ×1.5 | ×2.0 | ×3.0 |
|---:|---:|---:|---:|---:|
| 1 支 | S1 | S4 | S7 | S10 |
| 2 支 | S2 | S5 | S8 | S11 |
| 3 支 | S3 | S6 | S9 | S12 |

每个资源设置在多个维修效率种子下运行四种机制。同一种子内四组共享完全相同的 `xi_a^t`，以配对方式估计滚动重规划的绩效差。

### 3.3 每周期流程

```text
读取已观测修复进度、剩余供给和累计配送量
    ↓
固定计划更新，或对候选道路执行一步前瞻评价
    ↓
实现本期维修效率，观测实际修复进度与容量阶段
    ↓
按车型阈值构造四张车型相关动态路网
    ↓
计算供给点到需求点的车型相关最短路
    ↓
按残余边—周期容量重算可行路径并分配车辆趟数
    ↓
执行最大—最小公平配送，再分配剩余资源
    ↓
记录可达率、满足率、路径变化和修复状态
```

### 3.4 修复进度与动态通行时间

```text
p_a,t = min(1, p_a,t-1 + xi_a,t * 投入工时_a,t / 调整后修复时间_a)
B_a,t = capacity_a * g(p_a,t) * 8h * capacity_scale
tau_a,v,t = free_time_a / s(p_a,t)
```

`xi_a,t` 在本期维修决策后实现，期末观测的 `p_a,t` 决定吞吐阶段、速度阶段和车型可通行性，并作为下一期滚动决策的新信息。车辆 v 仅在 `p_a,t >= theta_v` 时可通过道路 a。每执行一趟配送，从路径各路段扣减 `pcu_per_vehicle_v`；容量不足时在残余网络中寻找绕行路径。

### 3.5 与正式目标一致的一步前瞻修复规则

```text
DeltaU_a = Σ_d r_d,t(before) - Σ_d r_d,t(after a)
DeltaH_a = min_d h_d,t(after a) - min_d h_d,t(before)
DeltaC_a = C_t(before) - C_t(after a)

选择规则：按 (DeltaU_a, DeltaH_a, DeltaC_a) 进行字典序最大化
```

对每条尚未完成的候选道路，模型假设投入当前维修队的剩余周期工时，更新该道路的修复进度、容量阶段和车型通行条件，然后运行与正式实验相同的公平配送程序。`DeltaU_a` 是本期未满足需求减少量，对应正式目标 F1；`DeltaH_a` 是最低满足率改善量，对应 F3；`DeltaC_a` 是配送时间减少量，对应 F2 的配送时间部分。模型首先最大化 `DeltaU_a`，完全相同时再依次比较 `DeltaH_a` 和 `DeltaC_a`，仍相同时按道路编号确定性破同分。

修复时间不设置额外惩罚项，而是通过 `投入工时 / 道路修复时间` 决定候选动作能够产生的进度增量。车型阈值也不设置额外奖励；跨越阈值后产生的配送量、最低满足率和配送时间变化会直接反映在三个评价量中。若维修队提前完成短任务，则使用剩余工时重新评价下一条道路。该规则是与正式目标方向一致的一步前瞻策略，不等同于剩余规划期的全局多目标优化。

### 3.6 配送规则

每周期先在当期可达需求点中求解最大—最小满足水平，再向仍有缺口且不超过全局供给比例上限的需求点分配剩余资源。每辆车每周期最多执行一趟；配送量、车队数量和路径剩余 pcu 同时限制可执行趟数。每个供给点—需求点组合选择残余容量网络中通行时间最短的车型；通行时间相同时优先选择载重更大的车型。配送优先级按需求量从大到小排序。

### 3.7 随机性口径

修复候选完全并列时按道路编号确定性破同分。随机性只来自道路—周期维修效率 `xi_a^t`；默认 `delta=0.30`，即 `U(0.7,1.3)`。同一种子下所有机制共享同一随机实现。正式实验至少使用 `delta=0/0.15/0.30` 和足够多的随机种子，并在资源设置内报告配对差值、置信区间和效应量。

## 4. 评价指标

| 指标 | 公式或定义 | 方向 |
|---|---|---|
| 周期总满足率 | S_t = Σ_d min(u_d,t,D_d) / Σ_d D_d | 越大越好 |
| 累计未满足率和 | CUA = Σ_t (1−S_t) | 越小越好 |
| 最终总满足率 | S_T | 越大越好 |
| 最终最低满足率 | min_d(u_d,T/D_d) | 越大越好 |
| 周期可达率 | 当期可达需求点数 / 35 | 越大越好 |
| 平均可达率 | Σ_t Reach_t / 9 | 越大越好 |
| 首次配送周期 | 首次出现正配送量的周期 | 越早越好 |
| 路径切换次数 | 相邻周期最优路径节点序列变化数 | 描述性 |
| 部分恢复道路—周期数 | Σ_tΣ_a I(0<p_a,t<1) | 描述性 |
| 最大边—周期利用率 | max(L_a,t/B_a,t) | 不得超过 1；判断容量是否绑定 |
| 高利用率边—周期数 | Σ_tΣ_a I(L_a,t/B_a,t≥0.8) | 描述瓶颈强度 |
| 容量阻塞配送量 | 因拓扑可达但残余容量不足而未执行的目标吨位 | 越小越好 |
| 车辆趟数 | 各车型本期实际执行趟数总和 | 描述性 |
| 修复进度预测 MAE | 实际期末进度与按 `E[xi]=1` 预测进度的平均绝对差 | 描述信息冲击强度 |
| rolling 配对收益 | 同一随机实现下 open-loop CUA − rolling CUA | 越大越好 |
| 相对完全信息方案 regret | 策略目标值与完全信息上界的差 | 越小越好；待实现 |

累计未满足率和是以“周期”为步长的归一化离散积分。代码未乘以 8 小时，因此数值单位是周期而非小时；如需换算为未满足率—小时，可将结果乘以 8。相对改善率按 `(基线−处理)/基线×100%` 计算。

## 6. 结果解释与 Proposal 表述

### 6.1 渐进恢复的独立贡献

二元静态和渐进静态使用相同修复计划，因此差异来自部分恢复道路提前进入车型相关路网。小型车辆不必等待道路完全修复即可通行，新连接更早参与路径优化。

### 6.2 道路状态信息的独立贡献

当前 open-loop 和 rolling 使用相同的一步前瞻评价规则、相同的期望维修效率与共同随机数。open-loop 在期初沿期望状态轨迹生成完整规划期方案；rolling 则在每一期把已经实现的修复进度、容量阶段、车型可通行性、累计配送和剩余供给作为新初始状态，重新求解剩余问题。因而两者差值只在实际状态偏离预测状态后出现，`delta=0` 的结果一致性是必要的安慰剂检查。

### 6.3 为什么不能只报告最终满足率

当总供给固定为需求的 79.73% 且所有需求最终可达时，不同机制会收敛到相同最终满足率。只报告期末结果会掩盖黄金 72 小时内的时效差异。累计未满足率和与逐期可达率是更有区分度的过程指标。

### 6.4 当前可直接用于 Proposal 的结论

> 本研究将道路修复刻画为逐期渐进恢复过程。期初方案依据期望维修效率生成；执行中实际维修效率使道路修复进度、容量阶段和车型可通行性偏离预测，滚动策略据此更新剩余规划期的修复与配送决策。研究采用共同随机数下的 open-loop/rolling 配对比较，并设置无维修效率偏差的安慰剂情形，以识别道路状态信息本身的价值。具体效应量将在多资源设置、多随机种子的正式实验后报告。

## 8. 局限性

1. 道路容量是补充估算值，并非逐路段实测值。
2. 恢复阶段和车型阈值尚未由现场观测标定。
3. 通行时间由独立速度恢复系数计算；未纳入普通交通流和流量驱动 BPR 函数。
4. 每辆车每周期最多一趟，但未显式模拟往返、装卸和跨周期占用。
5. 单车 pcu 采用 1.0/1.5/2.0/2.5 的待标定场景值；默认估算容量在 S8 中最大利用率仅约 5.7%，不形成瓶颈。
6. 本研究不单独建模维修队移动路径；假设维修队已预部署，任务间转移、准备和布置时间较小或已计入道路修复时间。该范围假设不适用于维修队跨区域长距离调度场景。
7. 滚动修复采用与正式目标方向一致的一步前瞻字典序规则，但仍是局部启发式，不能证明达到全局最优；正式效率目标使用配送时间与维修作业工时的加权和，权重 0.05 仍需敏感性分析。
8. 12 个情景都基于同一汶川网络，资源敏感性不等于跨网络外部有效性。
9. 当前随机网络参数下第 1 期即全部可达，区分度不足。
10. 12 个资源设置是设计点而非独立样本；随机维修效率种子是模拟重复单位，统计推断应采用资源设置内的配对分析。

## 9. 后续实验建议

### 9.1 优先增强机制证据

1. 对恢复阈值、容量比例和字典序目标优先级做系统敏感性分析。
2. 增加“无车型差异的渐进恢复”组，区分容量恢复与车型阈值贡献。
3. 对效率目标中维修作业工时权重 `lambda_R` 做敏感性分析。
4. 设计会造成关键需求点断联的随机网络，开展跨网络重复实验。

### 9.2 提高模型真实性

1. 先校准单车 pcu 和道路容量，并重跑 `capacity_scale=1.00/0.05/0.02` 的敏感性网格。
2. 跟踪车辆往返、装卸和跨周期占用。
3. 使用道路等级、车道数或交通部门数据替换容量估算。
4. 使用现场抢通标准或专家判断标定恢复阶段。
5. 取得普通交通 OD 后，再引入背景流与 BPR 通行时间。

### 9.3 后续算法实验

机制模型稳定后再比较标准 NSGA-II、NSGA-II + ALNS 和小规模精确解。算法实验应报告 Pareto 前沿、超体积、IGD、运行时间和多随机种子分布。
