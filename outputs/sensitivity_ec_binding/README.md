# EC 过渡带敏感性格子（冻结敏感性方案的 EC 轴）

日期：2026-10-14。目的：把容量利用率推到 0.85–0.97 过渡带附近，判断 EC 约束是否改变规划或执行结果。背景：默认标定（`capacity_scale=0.05`）实测利用率仅 0.010–0.034，Full 与 No-EC 在所有已测预算下都无差异；机制报告的网格显示绑定要到利用率 ≈0.97，且 0.97 不是充分阈值（M100 有反例）。

## 设计（跑前声明，见 `protocol.json`）

- 案例 S025；实例种子 1–10；求解种子 `90000 + 实例×10000 + repeat`，repeat 0–3。
- 容量档：**0.005 / 0.002 / 0.001**（目录前缀 `cap005` / `cap002` / `cap001` = 档位 × 1000）。
- 对照模型：`PR1_HT1_EC1`（Full）与 `PR1_HT1_EC0`（No-EC）；算法 `nsga2`；预算 10000；种群 32。
- 共 3 × 10 × 4 × 2 = **240 次运行**，单模型 RunStore，12 并发。
- `capacity_scale` 属于物理实例指纹：每个容量档是一个独立物理场景，档内做配对比较（Full vs No-EC，同实例同种子）。

## 执行记录

- 三档批次（240 次声明）跑到 **34/240 时停止**：实测利用率斜率显示 0.005/0.002/0.001 三档最高只到约 0.75（低于 0.85 过渡带入口），对"要不要考虑 EC"的判断不够有信息量；已完成的 34 个运行保留（cap005 档 17 个配对单元），未完成部分可用 `--resume` 随时补跑。
- 追加**极值探针**（`probe_commands.sh`，8 次运行，声明见 `protocol.json` 的 `probe_addition`）：`capacity_scale` 0.0005 / 0.0002（外推利用率 ~1.5 / ~3.7，确定性绑定）× 实例 1–2 × 种子 repeat 0 × {Full, No-EC}。判定看三件事：决策哈希是否改变、执行目标差多少、`capacity_blocked_tons` 是否 > 0。

## 探针结果（2026-10-14，四对配对均在 Full 共同执行环境回放）

| 档（最忙边利用率） | 实例 | Full 计划执行 F1/F2/F3 | No-EC 计划执行 F1/F2/F3 | 决策 |
|---|---:|---|---|---|
| cap5e4（~0.99） | 1 | 3.606 / 2852.5 / −0.900 | 3.627 / 3083.5 / −0.900 | 异 |
| cap5e4（~0.99） | 2 | 3.907 / 2710.8 / −0.900 | 3.937 / 2680.2 / −0.900 | 异 |
| cap2e4（~3.7，硬绑定） | 1 | **3.834** / 3549.4 / **−0.900** | **4.842** / 3465.5 / **−0.152** | 异 |
| cap2e4（~3.7，硬绑定） | 2 | **4.062** / 4019.0 / **−0.900** | **4.854** / 4451.7 / **−0.304** | 异 |

结论：**EC 有条件地有价值**。四对里规划决策全部不同（约束进入决策）；在贴边档（~0.99）执行差异很小；在硬绑定档（~3.7），无视容量去规划的方案执行时 F1 高 20–26%、最差期满足率从 0.90 崩到 0.15–0.30（F3），F2 两实例方向相反。动作阈值在利用率 ~0.85–0.99 与机制报告的过渡带一致。

## 与冻结协议的关系

本目录对应 `docs/formal_experiment_protocol.md` §5 的 EC 轴。探针表明原定三档（0.005/0.002/0.001，利用率 ≤~0.75）低于动作阈值、信息量低。2026-10-14 已按协议演化流程将 EC 轴水平改为 **{0.0005, 0.0002}**（生效点 + 硬绑定），协议 §5/§7 已同步（格子数 22→20，敏感性成本 ≈100→94 核时）。
